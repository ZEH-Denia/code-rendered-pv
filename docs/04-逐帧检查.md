## 三、发现并修复的问题

### 问题 1：grad-cam 特写裁到发顶（68 s）— 已修

**根因**：渲染期的 `sprite_src` 被 `h3_full.sprite_src` 替换，读的是**舞者缓存**（420×540），其 `face` 像素框 `(80,80,335,250)` 是按全身站姿定的；半身像素材的脸在 y 250–400，于是框到了发顶。

**修法**：`h3_full` 四个框按半身像重定（`face (60,230,360,420)` 等），`tuikit.CROPS` 同步；并给 `halfblock` 加 `contrast` 参数解决浅色插画在 8 级量化下发糊。

### 问题 2：EXECUTION 眼带位置错（147 / 151 / 155 s）— 已修

**根因**：`f2_closeup.EYES = ((211.3,216.3),(292.5,196.3))` 是**原立绘的虹膜坐标**（CROP 坐标系）。换成半身像后，她的闭眼实际在 y≈305、且是水平的（原立绘头是歪的，角度 -13.8°）。所以那条「砸在她眼睛上」的 EXECUTION 带子斜切在脸颊/嘴上。

**修法**：按新素材重测 → `EYES = ((180,305),(285,305))`，角度归零。
修后：带子正压在双眼上，画面对齐了「遮住眼睛」的原意。

修复前后对照见 `眼带修复.png`。

## 四、未改动、但值得知道的

1. **141 s 奖励矩阵仍偏红/黄**：这是 ANOM（警告）语义色 `#FFBE78`，在粉色主调里显得偏黄。若要更统一，可以再往玫瑰金压一档，但会削弱"警告"的可辨识度。
2. **176.8 s 有 3 帧接近全黑**：设计上是「她最后一格光点飞出」的过场，不是丢帧。
3. **44 s 的「我可以×N」文字墙**：这是 A3 段模型退化的原设计，会一路铺到窗底被容器裁掉（聊天窗本来就是 overflow:hidden），不是排版错误。
4. **歌名/歌词条/素材署名**：仍是 Mili 原作与 CC 署名，按版权要求保留。

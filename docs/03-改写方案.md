## 二、为什么这个角色和这支片子严丝合缝

1. 片子本来就是"她是一个被训练、被改写、被删掉的容器"——**和"残星会的实验体/阿列夫一的容器"是同一个母题**。
2. 原片结尾：「我会一直在。」「你不用。」→ 正好是达妮娅「**渴望被拯救却主动拒绝救赎**」。
3. 原片最后一帧她打出「在吗？」——而**她的名字就是"再见"**。改成「再见？」这句双关是整个改编最值钱的一处改动。
4. 原片 110 s「你离开、页面被一层层拆掉」的位置，正好可以放她那句「不要看，不要听，然后忘掉吧」。

### 不改（以及理由）

- **歌名 / 歌词条 / 逐字时间**：版权归 Mili，且改动会破坏 `data/timing` 的时间轴校验。
- **署名、AI 生成标注、CC 协议**：必须保留（这是原作者与素材的授权链）。
- **技术文本**：`num_hidden_layers`、token 数、`EPERM`、PID、`loss=0.8591` 等——片子"像真终端"的质感全靠这些。
- **"你"的台词**：`你会一直在吗？`、`你是谁？`——她的回答改了，你的提问不用改，反而更有张力。
- **A3 选择题选项**（一个点/一个圆/一条正弦曲线/无穷）：和歌词 "set of points" 直接呼应，动了会脱钩。

## 十二、grad-cam 取景修复（2026-11-08 00:01）

### 现象
68 s 的 grad-cam镜头里，画面是一团浅粉的"糊块"，看不到脸。

### 根因（不是取景修正没生效，是**另一套裁剪框**没跟着改）

一条关键机制：**渲染期的 `sprite_src` 不是读立绘文件的**。

```
tuikit.sprite_src        读 expressions/whale-*.webp（935×1682 立绘）
        ↓ 被替换
h3_full.sprite_src       读舞者缓存 pv_cache/rgba/<take>/NNN.png（420×540）
```

`h3_full` 里有一套**像素**裁剪框，是按"全身立绘站姿"定的：

```python
boxes = {'full':(0,60,420,540), 'upper':(0,70,420,350),
         'bust':(40,70,390,310), 'face':(80,80,335,250)}
```

我们的素材是**半身像**，被摆在 420×540 画布的底部（人物 y 123–528）。所以 `face` 框 y 80–250 落在**发顶/额头**——脸在 y 250–400。

### 修法

1. `h3_full.py` 的像素框按半身像重定：
   `full (0,120,420,540)`／`upper (20,140,400,400)`／`bust (20,140,400,470)`／`face (60,230,360,420)`
2. `tuikit.CROPS`（静帧与预览走这条）同步改成该素材的比例：
   `face (0.35,0.09,0.80,0.25)` 等
3. 顺带修可读性：给 `halfblock` 加了 `contrast` 参数——浅色插画在 8 级量化下会糊成一团，grad-cam 用 `contrast=1.8` 才看得清睫毛、嘴、发饰。

## 十三、发送按钮改为同色系哑玫（2026-11-08 00:30）

### 问题
发送按钮此前是 dsh 的品牌蓝 `#679EFE`（`--dsw-alias-button-info-fill` → `--dsw-static-deepseek-400`），是全画面唯一还亮着的冷色，跟樱粉主调打架。

### 改法
不改组件 CSS，只覆盖两个主题变量（`seg.html` 的共享调色板 + `build_frame.py` 的等价块）：

```css
--dsw-alias-button-info-fill: #8e4a6b;    /* 哑玫：同色系但压暗一档 */
--dsw-alias-button-info-hover: #a0597c;
--dsw-alias-link: #e289ac;                /* 链接仍用亮一档的粉，保证可读 */
--dsw-alias-state-business-primary: #c4688f;
```

### 为什么是 #8E4A6B
对比度：白色箭头在 `#8E4A6B` 上 **6.28:1**（原蓝色 4.33:1，主粉 #FF6FA5 只有 2.60:1）。
它比主色暗一档、饱和度也低，所以在对话框里"同族但退后"，不会抢走视线。

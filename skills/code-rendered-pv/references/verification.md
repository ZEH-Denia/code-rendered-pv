# 验收与 A/V 校验

分层验：**成片规格 → 全帧指标 → 人工抽样 → A/V 同步**。前一层不过就别做后一层。

---

## 一、成片规格（秒级）

```bash
ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height,r_frame_rate,nb_frames,sample_rate,channels -of default=nw=1 out/film.mp4
ffmpeg -hide_banner -i out/film.mp4 -af volumedetect -f null - 2>&1 | grep -E "mean_volume|max_volume"
```

| 必须核对 | 期望 |
|---|---|
| 帧数 | `round(时长 × fps)`（差 1 帧通常是 `-shortest` 裁的） |
| 时长 | 与歌曲/目标一致（±1 帧内） |
| 音量 | mean 不能是 −91 dB（那是静音占位音频） |
| 音轨 | 采样率/声道与源一致 |

---

## 二、全帧指标（2–3 min，覆盖每一帧）

把视频解成 rawvideo，逐帧算指标，存成 json 再分析：

```python
# 每帧
mean, std, p2, p99          # 亮度分布
diff                        # 与上一帧的平均绝对差
blue / pink_ratio           # 色相占比（验证改色是否彻底）
ink in margins              # 底部/右侧/顶部边带墨水（越界嫌疑）
```

判读规则：

| 指标 | 判读 |
|---|---|
| `mean < 3` 且连续 ≥3 帧 | 空帧/黑帧——确认是设计还是丢帧 |
| `diff < 0.15` 且画面有内容，连续 ≥1 s | 冻结/丢帧 |
| `diff` 局部极大 | 切点；再查**切点前后 2 帧**有无黑闪 |
| `blue_ratio > 0.05%` | 改色没彻底 |
| 边带墨水突增 | 排版越界（注意页脚署名是正常的） |

实测基线（212 s / 5085 帧的片子）：切点 91 个、黑闪 0、冻结 0、蓝像素超阈值帧 0。

## 三、人工抽样

- **1 fps 抽帧**（212 帧）拼成 4×6 接触表，9 张图通读一遍，看整体连贯与文字裁切。
- **高密度帧全分辨率复核**：找文字最密的几帧（左窗正文、系统提示、计数行），原尺寸看有没有行被容器裁断。

> 注意：这类片子里大量「乱码/抖动文字」是打字机特效（每个新字先闪随机字形再落定），**不是**渲染错误。判断标准是：静止帧上是否清晰。

## 四、A/V 同步（`scripts/check_av_sync.py`）

四件事，缺一不可：

1. **封装偏移**：按工程同一条滤镜链重建「应有的混音」，与成片音轨互相关。
   本次结果：lag **0 样本**，相关 **0.9993** → AAC encoder delay 被正确补偿。
2. **参考轨对齐**：用作者的 1 ms 响度包络做瞬态互配，本次中位 **+1 ms**。
3. **事件帧落点**：挑三个设计时刻，看对应帧是否精确跳变。
   本次：HARD_CUT 207.083 s → 帧 4970（亮度 10.2→0.0 正好该帧）；钟声 207.874 s → 帧 4989（0.0→0.5 正好该帧）。
4. **漂移**：把歌词带这类「画面侧时间刻度」的逐帧变化量与音频 onset 做互相关。
   本次：全片 lag 0；21 个 10 秒窗中位/众数都是 0。

### 判读要点

- 24 fps 的时间分辨率是 **41.7 ms**。所有「0 帧」的含义是**误差 < 41.7 ms 且不累积**。
- 分窗相关性低于 0.2 的窗口，lag 是噪声，别当漂移。
- 音轨开头若有 20–40 ms 静音是正常的（源文件自带），**不要**误判为延迟；看首样本是否从 0 平滑起跳（无爆音）。

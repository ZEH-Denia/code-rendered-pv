# 提示词模板

三套，按场景挑。填掉 `{}`。

---

## 主模板：从素材到交付物

```text
【任务】用 {素材} 做出 {交付物}。

【素材】{链接/路径/描述}
　　已知：{类型、时长/尺寸、来源、许可证}
　　未知：{我还不确定的地方，请你先查证}

【交付物】{格式 + 规格 + 命名 + 存放位置}
　　例：1280×720 / 24fps / 211.9s / out/film.mp4，附带无损母版

【硬约束】
　　· 磁盘 {剩余}，时间 {上限}，机器 {芯片/内存/系统}
　　· 禁止：{sudo / 改上游源码 / 发布或上传 / 商用素材}
　　· 允许替换：{缺的素材可用什么顶替}，但每处替换必须记账

【验收】（每条都要能被命令验出来）
　　· 环境检查通过
　　· 产物：{分辨率/帧率/时长/编码}
　　· 内容：{音频非静音 / 对齐误差 / 无版式溢出 / 抽帧位置}
　　· 可复现：另一台机器照文档能从零跑出来

【工作方式】
　　· 先冒烟再全量：先用替代品跑通最小闭环，再上真素材
　　· 每个偏差给三栏：现象 / 证据 / 处置，并复验
　　· 遇到止损条件就停下来问，不要猜

【回执格式】
　　1. 步骤 → 状态（✅/⚠️/❌）
　　2. 偏差表（现象 / 证据 / 处置 / 是否复验）
　　3. 验收表（条目 / 标准 / 实测）
　　4. 未做项 + 原因
　　5. 下一步建议
```

## 变体 A：只要评估，不要动手

```text
【任务】评估用 {素材} 做出 {交付物} 的可行性，不要修改任何文件。

【必须给】
　1. 结论：能做 / 有条件能做 / 不能做，一句话
　2. 环境对照表：{要求 / 本机现状 / 是否满足}
　3. 缺口清单 + 每一项的替代方案
　4. 时间与磁盘预算（按本机实测口径，不要空话）
　5. 已知会走样的地方，按影响排序
　6. 相关工具清单：必需 / 可选 / 明确别用（后两类各给理由）

【纪律】不确定的标"未验证"，不要拿通用经验冒充本机结论。
```

## 变体 B：指挥 / 执行分离

适合「一个模型出方案、另一个模型动手」或「人指挥、agent 执行」。

### 给指挥（只读沙箱）

```text
你是本项目的指挥官。执行者是另一个 agent，它会逐条执行你的编号指令并回执。

先读 ./交班单.md 与 ./现有评估.md。你可以读文件、跑只读命令核查，但不要修改任何文件。

输出三部分：
1) 决策：对交班单里每个待决问题逐条拍板
2) 编号指令：每条含【目的】【可直接粘贴的命令】【预期产物】【失败时怎么处置】
3) 验收标准：执行者做完应自检什么

约束：执行者只有 {shell/文件/包管理/ffmpeg/...}；不要下发需要 sudo 或交互式登录的命令。
```

```bash
# 只读沙箱能给"指挥"上物理约束，而不是靠自觉
codex exec --sandbox read-only --skip-git-repo-check --cd "$PWD" "……"
```

### 给执行者

```text
按编号逐条执行指挥的指令。规则：
· 逐条回执：做了什么 / 证据（命令输出、ffprobe、文件大小）/ 是否偏离
· 偏离指令时：先按【目的】做最小改动，然后在回执里单独列出（现象/证据/处置），不要静默改
· 做不到就说做不到，不要改方向
· 全部完成后给出验收表 + 未做项
```

### 交班单要写什么

```text
0. 执行者能做什么（工具、权限、沙箱、被禁的命令）
1. 任务背景与已经完成的调查（带真实数字）
2. 环境事实（机器、版本、磁盘、网络）
3. 必须替换 / 未解决的项
4. 用户最新意图 + 还没回答的问题
5. 请指挥决定的事（列成编号问题）
```

> 交班单写薄了，指挥只能瞎猜；写厚了，它能直接拍板。

## 改造类任务的一句话开场

> 「这是已经跑通的工程。我要把 {A} 换成 {B}，**不改** {C}。先按 `references/pitfalls.md` 的清单把常量全找出来，列给我，再动手。」

这句能省掉最容易返工的一轮。

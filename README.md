# code-rendered-pv

**逐帧渲染的 PV：工作流、模板，与一次真实的 macOS 复刻记录。**

> 本仓库的一切建立在原作者的开源工程之上：
> **[MisakaZentai / world-execute-me-dsh-pv](https://github.com/MisakaZentai/world-execute-me-dsh-pv)**
> —— 一支用代码逐帧渲染的 TUI 风格 PV（Mili《world.execute(me);》非官方同人）。原工程的画面引擎、镜头编排、网页前端拼装、逐帧合成全部由原作者完成；本仓库只做**移植、改造与验收方法**，不含原工程的源码副本。

---

## 这是什么

一份**可复用的技能**：教一个 agent（或一个人）怎么制作、改造、验收这类"每一帧都是歌曲时间 t 的纯函数"的片子。

以及一次**真实的落地记录**：把原工程搬到 macOS、把角色素材换成另一张插画、把人物改成另一套人格设定、把配色改成另一种色系，然后逐帧验收、做 A/V 校验、出 4K。

```
skills/code-rendered-pv/
├── SKILL.md                 何时用、三条铁律、七步闸门、五类坑、命令速查、实测标定
├── references/
│   ├── workflow.md          七步流程详解 + 止损规则 + 时间预算
│   ├── pitfalls.md          七类坑与「怎么查」（grep 清单）
│   ├── prompt-templates.md  主模板 / 只评估 / 指挥-执行分离
│   └── verification.md      规格 → 全帧指标 → 抽样 → A/V 四层验收
├── scripts/
│   ├── check_av_sync.py          封装偏移 / 事件帧 / 漂移
│   ├── check_song_alignment.py   歌曲毫秒偏移（用参考响度包络）
│   └── prepare_character.py      插画 → 抠图 / 立绘 / 舞者三套画布
└── templates/
    ├── setup-macos.sh        幂等装配
    └── run.sh                一键出片
```

三个脚本只依赖 `numpy` + `Pillow` + `ffmpeg`，已在一支 212 秒 / 5085 帧的成片上实测：

| 项 | 实测 |
|---|---|
| 成片音轨 vs 应有混音 | lag **0 样本**，相关 0.999268 |
| 歌曲 vs 参考包络 | 中位 **+1 ms** |
| HARD_CUT / 钟声 事件帧 | **±0 帧** |
| 全片与分窗漂移 | 中位 **0 帧**（24 fps 下即 < 41.7 ms） |

## 三条铁律

1. **先冒烟，再评估** —— 纸面评估必漏（格式假设、编码器参数、硬编码路径、裁剪框）。
2. **每个偏差都要记账并复验** —— 量出偏差、修、复量，三步缺一不可。
3. **验收必须可量化** —— 帧数、时长、dB、毫秒、像素占比，不是"看着还行"。

## 怎么用

把 `skills/code-rendered-pv/` 放进你的 agent 技能目录（例如 `~/.dsh/skills/`，或软链过去），然后：

> 「用 code-rendered-pv 这个流程，把 {素材} 做成 {交付物}」

或者直接读 `SKILL.md` 按七步走。
